# Model-Checking Findings

Chronological log of what TLC found, what it means for the protocol, and
what changed in the spec/design as a result. Traces referenced here can be
regenerated by re-running the configs (breadth-first search finds the same
depth counterexamples, module scheduling nondeterminism).

## F1 — The downgrade lamport clocks are load-bearing (13-step trace)

First model iteration omitted the clocks ("Stage 2, probably an
optimization"). TLC immediately produced: participant votes ready with
counts (0,0); a reference then passes THROUGH it (unpack -> promote out of
PENDING -> re-pack to the root); the root's tallies balance and it commits
while the reference lives on. The only mechanism in the real protocol that
catches a reference moving through a node AFTER its vote is the post-vote
clock bump (`bump_downgrade_lamport_clock` set by
`accumulate_local_references`, applied on the next pack), which poisons the
root's `downgrade_lamport_clock <= pending_downgrade_lamport_clock` check.

Consequence: clocks are modeled in Stage 1 (clk/pclk/bump per node, clk
piggybacked on ref/response/restart/update/regresp messages). Also worth a
comment in the real code: the clocks are not a heuristic, they are the
only defense for the vote-then-traffic interleaving.

## F2 — Referenceless by-handle responses are unsound; responses must
##      carry a counted creation reference (13-step trace)

Covering the by-handle SEND with a temporarily-held reference is not
enough: the response message itself carries no reference, so nothing stops
the object from being collected cluster-wide while the response is in
flight. The delayed response then materializes a zombie GLOBAL replica of
a dead object, on which local code can mint references before any defunct
reply arrives.

Design change: by-handle responses carry a counted creation reference
(sender does sent++, the replica is born holding it, the requester
releases it when done). The in-flight response then keeps the counts
unbalanced, so no round can commit while it travels. This subsumes most of
the defunct machinery and replaces the "acquire-failure tolerance" design
question: the failure arm is only about what to send the REQUESTER when
the acquire fails (the object is already dying), not about protocol
soundness.

## F3 — Count cancellation through an unregistered replica (19-step trace)

n1 packs a creation reference to brand-new replica n2, then roots a round
before n2's registration reaches the owner space; n2 packs a reference
back to n1. The round tallies only n0 and n1: n2's uncounted sent and
uncounted recv are symmetric and CANCEL, the tallies balance, and the
round commits while n2 holds a live reference. The clocks do NOT catch
this: n2 never voted, so its packs never bump past the epoch.

The composition that closes it (verified):
  1. pack_global_ref waits for registration (pre-existing in the code);
  2. an unpack on a node with an active round sets
     pending_downgrade_restart (the stashed attempt added this);
  3. EVERY ready vote -- leaf, relay, and root decision -- refuses while
     pending_downgrade_restart is set, then clears it (the stashed attempt
     had this at the root and relay but MISSED the leaf vote path in
     check_for_downgrade, so it still had this hole).
Causality then guarantees the retry round includes the new replica:
flag => an unpack happened => the packer was registered => the owner space
knows the packer before the retry's fan-out.

## F4 — Two liveness holes in the non-blocking registration design
##      (wedge traces, found by EventualCollection)

(a) Registration nudge. A registration landing at the owner space after it
has already voted (PENDING, its round undecided elsewhere) adds the new
instance to remote_instances -- and the information dies there: the
downgrade owner waits forever for a restart that no one sends. The
non-blocking replacement for the stashed attempt's registration freeze:
registration handling must nudge the downgrade owner (a fire-and-forget
DowngradeRestart naming the owner itself), or re-run the downgrade check
locally when the owner space IS the owner.

(b) Rollback on ownership transfer. Ownership transferred to a node still
PENDING from the failed round wedges: a PENDING owner cannot start rounds.
Receiving a DowngradeUpdate is proof the round the receiver voted in
failed (the root only transfers on a failed decision), so the receiver
rolls PENDING back to GLOBAL and clears its vote receipt. This is the
abort rollback of the stashed two-phase design, piggybacked on the
existing transfer message with zero additional messages or phases.

## Artifact (not a bug): round-budget exhaustion

Restart-driven ownership transfers ping-pong (n0 <-> n1) while references
settle, consuming one round id per hop; with MaxRounds = 4 the liveness
config wedged one round short of the final commit. Raising MaxRounds to 8
verified full convergence. Real-protocol implication: restart handoffs are
message-wasteful but terminating (each restart is consumed exactly once).

## F6 — Design review (2026-08-17): reclassifications and two new master findings

Rulings adopted from the review: (a) handles need no packed references —
the runtime guarantees SOME node holds a covering global reference from
serialization until remote uses complete (e.g. IndexTask covering its
launch space for remote point tasks); (b) a registration reaching a dead
owner should be impossible under correct use, and hanging there is the
desired tripwire; (c) master completes all round messages before the next
round starts, so stale-ownership adoption is not a master bug.

Consequences applied to the model (v2):
- Creation references and the defunct reply are REMOVED from the design.
- Spawn now models the covering invariant (a pinned reference on any node,
  released by an unpin token after the remote use completes).
- Ownership versioning is retained, rejustified: it guards the restart
  FORWARDING fix (#7), which re-introduces out-of-round restarts that
  master avoids only by dropping them (the leak).

New findings from re-verification under the covering invariant:
- F6a (#10, master): a late registrant that missed the committing round
  can mint a local gc reference from zero (check_global_and_increment's
  GLOBAL fast path) in the window before the success broadcast reaches it;
  master's force-apply then downgrades it with gc_references > 0 (debug
  assert / release UB). Reachable iff any path upgrades a by-handle
  replica from a bare resource ref outside a covered window.
  Design answer (verified): an unseasoned replica (never unpacked a
  reference, never voted) routes its first from-zero acquire through the
  downgrade owner, where grant-vs-commit is atomic.
- F6b (#11, master): a covering reference minted locally from zero MID-
  ROUND is invisible to that round's tallies, so a by-handle record made
  during the recorder's outstanding vote escapes the round entirely: the
  commit is legal, the new replica strands (master cleans it up only via
  the force-apply), and its trailing registration can legally reach a
  DEAD owner -- master's blocking find then hangs on a non-bug. Design
  answer (verified): nudge at instance-RECORD time (update_remote_instances
  while PENDING sends a restart to the downgrade owner) + success cleanup
  applies to unseasoned referenceless replicas regardless of registration
  state. Residual: the record-time nudge can race the already-sent
  response, so a dead-owner registration remains reachable in a narrow
  window -- DowngradeCoverQ.cfg exists to produce that exhibit trace;
  the dead-owner registration semantics (ignore vs hang) is an open
  design question, including triggering the replica's remote_registered
  event when a success kills it before registration completes.
- RoundTagging: PASSED exhaustively with the toggle off -- redundant at
  Stage-1 scope (subsumed by the clocks); deleted from the design pending
  Stage-2 re-adjudication.

## F7 — Option A adopted (2026-08-19): counted + pre-registered by-handle creation

Design decision from review: by-handle responses are COUNTED like any
packed reference (sent++ at the sender with the clock piggyback, recv++ at
replica creation) and carry the registration handshake payload so the
replica is born registered — no trailing registration message exists for
owner-originated creations. A PENDING sender may not serve directly; the
implementation uses the existing pack_global_ref acquire fallback, whose
grant is serialized with the owner's decision (and under the covering
invariant can never fail — assertable).

Consequences:
- The object arithmetically cannot be collected while any creation
  propagates (the in-flight response keeps sent > recv): the coverq
  scenario is FIXED, not tolerated.
- DELETED from the design: seasoning, the from-zero acquire rerouting,
  the late-registrant success cleanup, the spawn-time nudge (all were
  compensations for half-integrated replicas, which no longer exist).
- DeadOwnerClean restored to its STRICT form; HandlesCovered promoted to
  a checked invariant of the main safety configs (registrations, which
  now only arise from ref-created replicas, provably cannot target a
  dead owner).
- Model fidelity fix found by the v3 smoke: DowngradeUpdate delivery must
  block until the target replica exists (the real handler's
  find_distributed_collectable), since a transfer may legally target a
  poison-nominated instance whose creation is still in flight;
  record-before-dispatch guarantees creation, and the in-flight transfer
  forbids a commit, so the wait is bounded and safe. Implementation note:
  keep the blocking/deferred find in the DowngradeUpdate handler.
- v3 liveness smoke: exhaustive PASS. Full matrix rerun in progress.

## F8 — Stage 2 (two levels): master finding #12 and the strict-order design

Master finding #12 (traces on first Stage-2 smokes): level ordering is not
enforced. Ownership can land on a GLOBAL-level replica of a still-VALID
object (via notready_owner from a mixed-level participant voting on gc
refs, via restart-candidate transfer, via the hairy registration handoff);
that owner roots a GLOBAL round (round level = owner's local state); the
catch-up rule (`while (to_check < current) perform_downgrade`) then forces
VALID nodes to invalidate WITHOUT any VALID-round commit -- hitting
legion_assert(valid_references == 0) in debug when valid refs are held,
invalidating referenced objects in release, and stranding in-flight valid
references/counts otherwise. Also: a GLOBAL replica participating in a
VALID round votes on its GC references and freezes at PENDING_LOCAL
(base-class record_pending_downgrade) -- a valid-round vote blocking
gc-level acquires.

Design ruling (review): downgrades across levels are COMPLETELY ORDERED
per object -- all copies must commit VALID->GLOBAL before the downgrade
owner may start GLOBAL->LOCAL.

Design realizing it (verified at smoke level):
- Every replica tracks the OBJECT level (olv, monotone V->G per lifetime),
  learned at creation (spawn/ref/registration payloads) and advanced only
  on commit proof: committing the V-round as root, receiving a V-success,
  or receiving olv=G from the ownership chain (updates, G-requests).
- The owner roots rounds at the OBJECT level, not its own state; a
  below-level owner/root/relay/participant contributes a trivially-ready
  vote with its (usually zero) valid-level counters, state untouched.
- Catch-up survives only as commit-proof application: PENDING_GLOBAL +
  a G-request or olv=G update applies the pending downgrade; a fully
  VALID node observing a GLOBAL round is a checkable impossibility.
- New invariants: ObjLvlSound (nobody believes the valid level dead while
  it is not) and StrictLevelOrder (no G-round/request/success exists while
  any replica is fully VALID or valid refs/messages exist; PENDING_GLOBAL
  overlap allowed -- agreement completes at the commit decision).

Model iterations found by smoke (design refinements, in the spec):
- F8a: rollback-on-transfer must be LEVEL-AWARE: an update carrying olv=G
  to a PENDING_GLOBAL node is a commit proof (apply the downgrade), not a
  failed-round rollback; blind rollback resurrected a committed V-vote.
- F8b: the commit proof applies even when the ensuing vote is not-ready.
- F8c: a below-level ROOT's own commit contribution is trivially ready
  (else it can never commit the V-round it correctly roots).

OPEN (Q-D): a valid reference legally packed toward a never-valid GLOBAL
replica of a live-valid object -- modeled as promotion to VALID
(object-monotone); confirm add_valid_reference's real semantics at GLOBAL
state, or forbid such packs.

Smoke status (per the design-before-verification rule, nothing more ran):
- Stage-2 liveness (strict-order design): PASS exhaustive (2 min).
- Stage-2 safety: clean through depth 22 / 87M states (bounded smoke).
- Old mode: DiedStaysDead violated in a 4-step trace (cross-level
  resurrection) -- two-level model validation.

## F9 — Stage-2 design simplified per review: replica state IS the object level

Review ruling on the olv proposal: unnecessary. Replicas start in the
known state of the object at the creator (VALID or GLOBAL), go to
PENDING_GLOBAL / PENDING_LOCAL on downgrade requests, and bump back up on
newly arriving references of the matching level. Adopted; the separate
object-level field, MixedLevelReady, and all below-level vote machinery
are DELETED from the design and the model.

The one addition the design needs (verified): the creator's state is a
snapshot that can go stale in flight, and master's acquire_valid
local-mints valid references from zero at any VALID-state node
(garbage_collection.cc:1805) — so a stale-VALID replica materializing
after the V-commit could mint a valid reference on an invalidated object.
Closure, in Option-A style: CREATIONS ARE COUNTED AT THE STAMPED LEVEL
(creator sent_valid++ when stamping VALID, replica received_valid++ at
materialization, in addition to the carried reference's own level count).
The VALID commit is then arithmetically blocked while any VALID-stamped
creation is in flight; stale replicas cannot exist; acquire_valid's local
mint stays exactly as master has it; Q-D becomes a checkable
impossibility. Catch-up survives as: PENDING_GLOBAL + G-round request =
commit proof, apply the pending downgrade (covers G-rounds legally
overlapping V-success propagation — agreement completes at the decision).

Smoke status (matrix gated on review sign-off):
- Liveness: PASS exhaustive. Safety: clean to depth 24 / 93M states
  (bounded). Old mode: DeadOwnerClean violated (validation).

## F10 — Stage-2 design bug found by the sapling matrix: stamp-counting
##       requires the unconditional clock bump (DowngradeBig, depth 19)

The stamp-counting rule (F9) as first specified interacted badly with
master's level-conditional clock bump: pack_global_ref does not bump the
downgrade lamport clock at VALID-state nodes ("global refs are irrelevant
to a valid round"). Under stamp-counting that is no longer true -- a
gc-ref pack from a VALID node carries a valid-level STAMP count. TLC
(DowngradeBig on sapling, 13.5 min, 19-step trace) composed: a post-vote
in-flight valid ref to n1 (its recv unreported), plus a post-vote
G-ref pack n1->n2 whose STAMP-receive at n2 exactly masked the missing
recv in the tally; no clock ever bumped; the VALID round committed while
n1 was fully VALID holding a valid reference (StrictLevelOrder violated).

Fix (in the spec; verified liveness-exhaustive locally): with stamped
creations, EVERY counted pack is an event at the stamped level, so the
clock bump applies unconditionally whenever the bump flag is set.
Implementation note: remove the
(current_state != VALID && != PENDING_GLOBAL) condition from
pack_global_ref's bump under stamp-counting.

Also demonstrates the budget-blindness caveat: the base config
(MaxPacks=2) could not express the 3-pack trace -- larger-budget configs
are load-bearing members of the matrix, not just robustness margin.

## F11 — RegistrationGate is necessary at Stage 2 (cross-level instance-list blindness)

Stage 1 proved the gate exhaustively redundant; Stage 2 adjudication
(BisectRegistrationGate, job 77711) proves it necessary. Trace (28 states):

1. n0 spawns to n1 (counted, pre-registered), drops its ref; round V#1
   covers {n0,n1} and fails on tally imbalance (n1 packed 2 valid refs to
   n2 mid-round).
2. n2 is a REF-CREATED replica: it sends reg(n2->n0), which stays IN FLIGHT
   for the whole trace. Gate off => nothing stops n2 from participating.
3. n1's response reports the new instance, so ownership transfers to n2.
   The UNREGISTERED n2 becomes downgrade owner, runs round V#2 over
   {n0,n1,n2}, tallies balance (3=3), and COMMITS the valid level. This
   commit is arithmetically legitimate — n2's V-level counts are in the
   round because n2 is the round owner.
4. n0 had acquired a G ref, so the first G round transfers ownership back
   to n0. n0 drops the ref and starts round G#4 over its instance list —
   which is still {n1}, because n2's reg was never processed. All G-level
   counts are zero and BALANCED without n2: n2's only counts live at V
   level, already retired by the V commit.
5. G#4 commits; n0 dies LOCAL while n2 sits alive at GLOBAL, unregistered,
   reg message still in flight. DeadOwnerClean violated.

Why the level structure matters: within one level, a missing instance is
always visible as a tally imbalance (its recv counts are unmatched). Across
levels that protection evaporates — an instance whose counts were consumed
by the V commit is INVISIBLE to G-round arithmetic. The instance list is the
only cross-level continuity, and registration is the only thing that
maintains it. The gate ("cannot vote ready before registration completes")
forces the reg to be processed before any round the replica participates in
can commit, which puts it in the owner's instance list before the next
level's round starts.

Implementation note: ref-created (unpack-created) instances must not vote
ready in any downgrade round until their registration with the owner space
is acknowledged. Spawn-created (by-handle, Option A) instances are
pre-registered by the handshake and unaffected. RegistrationGate moves from
deletion-candidate to REQUIRED.

## F12 — Implementation-refinement race in the registration gate (CI crash)

Not a model or design bug: an implementation infidelity. The model's
RegistrationGate is an ATOMIC guard inside one action; the
implementation refined it into a blocking wait on remote_registered
that RELEASES gc_lock. Two threads whose remaining_responses==0 guards
passed under earlier lock holds can both enter check_for_downgrade,
both release at the gate (the field holds already-triggered events
indefinitely, since it is consumed lazily), and the first to reacquire
fans a round; the second trips the post-wait
`legion_assert(remaining_responses == 0)` (gc.cc:1230, 2-node CI
crash, 2026-08-21). A second window of the same family: the
commit-proof catch-up's perform_downgrade releases the lock for
notify_invalid before check_for_downgrade.

Fix: (1) never release the lock for an already-triggered registration
event; (2) after any genuine wait or downgrade-callback release,
re-check remaining_responses -- a racing thread's round subsumes the
check; a voter answers the always-safe not-ready so the round owner
retries. Lesson recorded: when refining an atomic model guard into a
blocking wait, every lock release needs a re-validation of the
enclosing action's enabling condition.

F12 addendum (full audit of every gc_lock release in the protocol):
two more instances of the family found and fixed. (a) The commit-proof
path in ValidDistributedCollectable::process_downgrade_update cleared
pending_downgrade_restart after perform_downgrade's callback release; a
fresher transfer racing through the window could start a round whose
unpack-veto the clear would erase -- now early-returns (flag preserved)
when remaining_responses > 0 on reacquire. (b) The gate fix's
raced-voter branch itself cleared the flag while an aggregation was
open through the node -- clear removed. Rule applied consistently: the
flag may only be cleared at a not-ready vote or decision taken with
remaining_responses == 0 under an unbroken lock hold. All other
releases audited clean: pack registration waits and debug fallbacks
re-read state on reacquire (master-existing); perform_downgrade's
guard-reference pattern re-validates via can_delete; the
update_remote_instances iterator wait precedes all branch evaluation.

F12 closing audit (static, per Mike's direction -- no model extension):
final composed text of all six lock-window sections re-read and
verified; all veto-flag sites classified (6 sets, 8 clears) against the
uniform rule; one residual exception hardened: both
process_downgrade_update paths now clear the flag only when
remaining_responses == 0 (previously unconditional -- model-verified
safe within its action set and hand-argued unreachable in the impl, but
the hardening makes the rule exception-free). round_owner audited: set
exactly once (after the gate, ordering load-bearing: a raced
early-return cannot corrupt an open aggregation's routing), all seven
uses round-scoped. Clock-token audit: encode/decode confined to
pack/unpack/acquire-grant; all protocol messages carry raw clocks; the
~35 two-step call sites verified opaque by provenance. Stamp hooks:
dispatch endpoints are same-class by DID; promotion guarded by
tripwires; unreachability of the dangerous cases is model-backed.
Verdict: the model-to-code gaps are closed by this audit; no further
analysis planned.

## F13 — Misrouted downgrade responses for non-member instances of
## collective mappings (2026-08-24 fuzzer failures; LATENT IN MASTER)

Triage of the fuzzer crashes (slurm-77759/77760): two assert
signatures, one root cause, found statically.
- Requests to NON-TREE remote instances of a collective-mapped DC are
  fanned directly by the tracking node (owner-space or a tree member
  with its own remote_instances), which counts them in ITS
  remaining_responses. The instance's RESPONSE, however, routed via
  get_downgrade_target -> CollectiveMapping::find_nearest(local) --
  the member nearest BY ADDRESS-SPACE ID (collectives.cc:2243), which
  is generally NOT the sender.
- The misrouted response decrements an unrelated member's aggregation
  (usually a relay of the same round): that relay answers its parent
  EARLY while the true sender's aggregation NEVER drains. Decisions
  then run on corrupted counts with responses still in flight; late
  responses land on retried/transferred rounds:
  Mode A (gc.cc:1657, downgrade_owner==local assert at the decision) =
  a late response reaching a root that already transferred ownership
  and re-rounded; Mode B (gc.cc:1214, remaining_responses==0 at
  check_for_downgrade) = the next round's requests reaching nodes
  still wedged mid-aggregation.
- MASTER has the identical routing and asserts but its fuzzer is
  clean: in master a wedged round simply never completes (restarts
  were dropped, no nudges, no retry-on-veto) -- a SILENT LEAK. The new
  liveness machinery pokes wedged rounds back into motion over the
  corrupted state, escalating the latent leak into visible asserts.
- The verified model always routed responses to the REQUEST'S SOURCE
  (rd.par); get_downgrade_target recomputed topology instead and got
  it wrong exactly for non-members. FIX (uncommitted): new
  round_parent member records the requester in
  process_downgrade_request; all five response paths use it;
  get_downgrade_target deleted. This aligns the implementation with
  the already-verified flat-model semantics; the Stage-3 tree model
  (next) verifies the tree specifics.

## F14 — Restart-transfer through the registration-gate window
## (fuzzer 2026-08-24 round 2, slurm-77768; Mode A only, Mode B gone)

After the F13 fix the fuzzer still hit gc.cc:1633 (`downgrade_owner ==
local_space` at the root's decision; 29 hits, all replicate values) in
debug mode. Static sweep of every downgrade_owner write showed no
single-lock-epoch path can move ownership away from a mid-round root;
the cause is a LOCK-RELEASE WINDOW plus a MISSING MODEL GUARD in the
implementation:

1. A fresh replica unpacks a ref, registers (ack in flight), becomes
   downgrade owner via the hairy handoff, drops its ref -> can_delete
   validates its belief -> check_for_downgrade(owner==local) hits the
   REGISTRATION GATE and releases the lock to wait.
2. A restart arrives in the window (e.g. the owner-space's nudge for a
   second registrant). The model's restart-ready check includes
   `RegistrationGate => reg`; the implementation's path had NO
   registration check, so it TRANSFERS ownership (downgrade_owner =
   candidate, version++) out from under the gate-waiter.
3. The waiter wakes; the F12 raced check tests only
   remaining_responses > 0 -- a restart-transfer leaves it 0 -- so it
   falls through and roots a round under a stale belief. Decision ->
   assert. No request ever reaches a busy node, which is why Mode B
   (gc.cc:1214) disappeared with F13 while Mode A survived.

Classification: NOT a model gap -- the model had the guard and the

- check_for_downgrade's post-gate raced check also returns when

## F15 — Use-after-free across the registration-gate wait (CI hang,
## caught by Mike in gdb, 2026-08-24)

The registration gate in check_for_downgrade releases gc_lock and waits
on remote_registered with NO reference pinning the object. On the
reference-dropping funnel (any remove_*_reference -> can_delete ->
check_for_downgrade; most acutely a message handler's trailing
remove_base_resource_ref, e.g. DistributedDowngradeRestart::handle) the
caller has just surrendered its only pin, so other threads can drive
the object to LOCAL and delete it during the wait; the reacquire then
touches recycled memory (observed: vtable cleared, did == 0, hang on a
garbage lock event). The blocking wait was an implementation
embellishment: the model's registration gate is an ENABLING CONDITION
(unregistered => vote not-ready / don't start; progress via the
verified RegHandshake nudge), and the wait is now implicated three
times (F14's transfer window, its own F12 fix, and this UAF).

### Lock-release / blocking-site audit (both protocol files)

UNPINNED on the deletion funnel (must fix):
- W1 check_for_downgrade registration gate (gc.cc) -- the only one.

Guarded by design (safe). The lifetime rule, per Mike's correction of
the first audit draft: DELETION is the hazard, not state transitions --
a held RESOURCE reference prevents deletion at any state (can_delete
only deletes at resource count zero), and reaching LOCAL during a
window is harmless provided post-reacquire code re-validates state.
- perform_downgrade base (+resource guard): pins deletion directly;
  note its window runs with current_state ALREADY LOCAL.
- Valid override (+gc guard): the gc guard exists for protocol ordering
  (no G-level downgrade during notify_invalid); it protects lifetime
  one step removed, by keeping the G commit (which requires
  gc_references == 0) from reaching LOCAL where deletion is possible.

Pinned by caller contract (safe today; document, fragile if new
callers appear on drop paths):
- update_remote_instances iterator wait: all callers hold find-refs or
  counted refs.
- pack_global_ref registration wait + debug PENDING_LOCAL acquire: the
  packing cover contract (a counted cover blocks every round from
  committing => no replica reaches LOCAL) plus sender find-refs.
- check_global_and_increment remote acquire chase (master-era):
  standard acquire contract (caller holds a resource ref).
- PhysicalManager::collect's two waits (join-and-drain,
  remote-collection done.wait): callers (memory manager, mapper calls)
  hold the manager through registries/mapper objects with resource
  refs. All other physical.cc waits are mapper/task-side with held
  references.

Structural invariants worth comments/asserts:
- Nothing reachable from can_delete may block or release gc_lock
  un-guarded (state at can_delete).
- process_downgrade_response's retry cannot re-enter the gate only
  because remote_registered is consume-once; keep it that way.

### Resolution
Replace the gate's wait with the model's enabling-condition semantics:
if remote_registered exists and has not triggered, respond not-ready

## F16 — Re-rooted trees break the mid-round registration poison
## (Stage-3 model, DowngradeTree4, StrictLevelOrder violated at depth 22;
## 945M distinct states, sapling job 77779, 2026-08-24)

GENUINE PROTOCOL BUG in the new design, tree topology only, found by
the model before the fuzzer/CI. Counterexample (tree n0-(n1->n3),n2;
outsider n4; owner transferred to n1):

1. n1 owns and roots a V round. Re-rooted fan: owner-space n0 relays
   only to ITS re-rooted child n2, then closes its aggregation and
   responds -- while the round is still open at n1 waiting on n3,
   whose response path (n3->n1) BYPASSES the owner-space.
2. A new instance n4 (created earlier by a counted pack) registers at
   n0 in the window after n0's aggregation closed. The mid-round
   poison (notready_owner = registrant) is gated on the owner-space
   having an OPEN aggregation -- it misses. Only the nudge restart to
   the downgrade owner fires, and it RACES the round's decision.
3. n4 (registered, holding its valid ref) packs a valid ref to n3;
   n3 receives it, drops it, then votes ready. The tally now
   cross-matches: the original pack's sent (tallied at its sender)
   is matched by n3's recv, while n4's own (recv=1, sent=1) pair is
   INVISIBLE -- n4 never voted in the round. Arithmetic balances.
4. The nudge restart is still in flight. n1 commits the V level and
   fans the G round WHILE n4 IS FULLY VALID HOLDING A VALID
   REFERENCE. StrictLevelOrder violated; in the implementation this
   is a use-after-invalidate for the application (notify_invalid
   ordering broken) and the G request at a fully-VALID n4 fires the
   catch-up assert.

WHY FLAT IS IMMUNE (why Stage-2 verified clean): in the flat topology
the owner-space relays to ALL remote instances, so its aggregation is
open for the entire round; the enabling middleman pack must land at a
participant BEFORE that participant votes, which is BEFORE the
owner-space closes -- so the registration always hits the open-window
poison. Re-rooting breaks exactly this: the owner-space can close
early while responses flow around it.

IMPLEMENTATION CORRESPONDENCE: real. update_remote_instances' poison
is gated on remaining_responses > 0 at the owner-space; with re-rooted
collective trees the owner-space's count drains before the round
decides, and the nudge restart races the decision on the wire.

CANDIDATE FIXES (design ruling needed before encoding + verifying):
A. Registration as a CLOCK EVENT: when the owner-space processes a
   registration and its aggregation is closed, bump its lamport clock
   past its lastR; the handshake response carries the bump to the
   registrant, whose packs propagate it; any voter receiving such a
   pack then fails the round's causality check (clk <= rid) and votes
   not-ready. Race-free: rides the causal chain (handshake -> pack ->
   vote) instead of a racing restart. Closes the middleman leg; the
   no-middleman leg is already blocked by the tally imbalance. Reuses
   existing machinery (clocks + causality); costs one spurious retry
   per registration-during-round.
B. Do not re-root: always fan rounds through the owner-space-rooted
   tree (member owners send their request to the owner space, which
   relays and aggregates everything, restoring the flat structure
   where the poison is provably sound). Costs one extra hop per
   member-owned round and needs owner-excision in the fan.

### F16 resolution (fix A encoded + prototyped, 2026-08-24)
Model: RegClockBump toggle; RecvReg's non-poisoned path bumps the
owner-space clock to Max(clk, lastR)+1 and every outgoing registration
payload (handshake, nudge, hairy update) carries the bump.
RegClockBump=FALSE is provably identical to the pre-fix spec, so
sapling job 77779 doubles as the BisectF16 verdict. Local verdicts on
the fixed spec: degenerate equivalence intact (224,577 distinct,
byte-identical, toggle off); flat safety smoke WITH the bump passes;
liveness set reproduces all recorded verdicts.
Implementation (uncommitted): update_remote_instances' closed-
aggregation registration branch does downgrade_lamport_clock++ (the ++
dominates any committable in-flight round because accumulate folds the
round clock at every ready vote; a not-ready-voted round is already
doomed -- deviation from the model's Max(clk,lastR)+1, justified by
that argument). The bump reaches the registrant through a NEW
DISTRIBUTED_REGISTRATION_RESPONSE message that replaces the bare
event trigger: the registrant folds the clock UNDER ITS LOCK BEFORE
triggering remote_registered, so packs gated on the event observe the
bump. This also finally implements the model's RegRespMsg clock
payload, which the implementation had elided.

### F15/F16 final implementation shape (Mike's consolidation, 2026-08-24)
The DISTRIBUTED_REGISTRATION_RESPONSE handler subsumes the F15
continuation: it IS the model's RecvRegResp action. remote_registered
becomes a bool (default true; false between send_remote_registration
and the response); waiters use a lazily-created pending_remote_
registered event. The handler folds the F16-bumped clock, marks
registered, triggers waiters, and drains a parked
pending_downgrade_restart via can_delete -- the veto flag is now the
single deferral marker for both the gate's self-check and the restart
park. The DeferRegistrationCheckArgs meta-task, its guard-reference
dance, and registration_check_pending are all deleted. The handler
uses a blocking find + hard assert, justified by: an unregistered
replica cannot reach a deletable state (LOCAL requires a G-level
perform_downgrade, reachable only via a ready vote or a success after
voting -- both gate-blocked -- or catch-up, which stops at GLOBAL).

### F17 CORRECTED (2026-08-30, after Mike's covering-invariant challenge)
The "refless bystander" mechanism was WRONG. The true mechanism of the
gc.cc:1255 crashes is the SILENT COVERED PROMOTION: add_gc_reference
(and the debug variants) at PENDING_LOCAL promotes the state back to
GLOBAL -- uncounted, with no notification to the round owner
(gc.cc:212-213, 523-524, 542-543; valid-level analogs promote
PENDING_GLOBAL back to VALID). This is SOUND because of the covering
discipline: an unconditional add is only legal while a reference is
held somewhere, every gc-reference chain bottoms out in a
protocol-visible root (a held ref votes not-ready; an in-flight ref is
counted), so no round can commit while any chain is live. A replica
can therefore ready-vote, promote under a cover, release, and
legitimately receive the commit's success while at GLOBAL/non-owner --
with ANY reference counts (the captures' zero counts merely reflect
that equivalence sets are request-created and never exchange counted
references; pclk=1 in the captures shows the replica HAD voted).
Consequences:
- The count-gated assert weakening from the first F17 fix was TOO
  NARROW (a counted promoted replica would re-fire it); corrected to
  (LIVE-state) \/ (PENDING-state /\ non-owner). gc_references == 0
  stays strict at success application: post-commit no cover can exist,
  so no legal add can race the delivery.
- Findings (a) missed-success leak and (b) unlocked remote_instances
  map race are RETRACTED: any in-flight replication (request /
  response / registration window) is covered by the requester's
  analysis, a cover blocks the commit, so no add and no success can
  be concurrent with the commit fan. The unlocked map at gc.cc:1281
  is safe BY the discipline (worth citing it in the comment there).
- The model's CreateRefless extension modeled UNCOVERED creations
  (violating the discipline); its DeadOwnerClean violation was an
  artifact. Machinery reverted; the spec is back to the committed
  Stage-3 form. OPEN (Mike's ruling): a faithful model extension --
  covered uncounted adds at PENDING states with promotion, reusing
  the pins machinery -- would machine-check the covering-discipline
  argument itself (incl. "gc_refs == 0 at success delivery").
